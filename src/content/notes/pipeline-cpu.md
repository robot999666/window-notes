## 给指令的旅程分段

这份 Verilog CPU 项目采用简化的 MIPS 风格五级流水线，用于 ModelSim 仿真。取指、译码、执行、访存与写回分别承接一段工作，顶层数据通路连接控制单元、寄存器文件、ALU 与存储器。

先沿着一条指令查看 PC、指令内容、ALU 结果与写回数据，再把相邻指令放进同一个时间轴，是理解这份代码的一种阅读方式。测试台暴露关键状态信号，仿真脚本负责编译、启动测试与添加波形。

## 暂停也是流水线的一部分

这个设计使用保守暂停处理数据相关，没有采用转发。条件分支在 MEM 阶段确定，跳转与 jr 则在 ID 阶段重定向；暂停和冲刷用于处理相关与控制转移。

观察这些信号时，可以把“哪一级正在做什么”与“下一拍允许谁前进”放在一起理解。项目的指令范围包含算术、逻辑、移位、访存与控制转移，存储器还涉及字、字节和半字访问。

## 用预期状态核对理解

仓库保存当前测试程序的指令镜像和最终寄存器状态。对照预期结果与关键波形，能帮助定位理解中的偏差。当前公开说明针对仿真，不提供 FPGA 实测或生产 CPU 性能结论；保守设计也应结合其学习目标阅读。

## 先追一条指令，再看相邻指令

可以先选择一条简单指令，逐拍记录它位于哪一级、读取了什么数据、产生了什么结果，以及结果什么时候进入寄存器。单条路径理解清楚以后，再把两条存在数据相关的指令放在一起，观察保守暂停怎样改变它们的前进节奏。

| 阶段 | 可以追踪的内容 |
| --- | --- |
| IF | 当前 PC 与取得的指令 |
| ID | 指令解释、寄存器读取与跳转信息 |
| EX | ALU 运算与中间结果 |
| MEM | 存储器访问及条件分支确定 |
| WB | 最终写回的位置与数据 |

表格帮助建立阅读坐标，不意味着新增了一套仿真验证。具体信号名称与指令细节，应回到当前仓库的模块和测试台核对。

## 用暂停和冲刷解释一张波形图

暂停回答的是“当前哪些级可以前进”，冲刷回答的是“哪些已经进入的数据不应该继续产生效果”。这个项目没有采用转发，因而不能拿另一种数据通路的经验直接解释它的波形。把控制策略与设计目标一起记录，才能理解为什么某些周期看起来没有完成新工作。

阅读测试结果时，还可以同时记录指令镜像、最终寄存器状态与关键控制信号。只看最后一个寄存器值，可能无法解释中间的控制转移。当前说明针对 ModelSim 仿真，不把这些结果扩展为 FPGA 实测或处理器性能结论。
