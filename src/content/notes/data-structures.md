## 让知识点对应具体代码

这份 C++ 数据结构课程学习仓库，按基础练习、顺序表、单链表、顺序栈、顺序队列和二叉树整理代码。目录从线性结构逐渐走向树，便于按知识点阅读，也方便在复习时找到对应实现。

同样是保存一组数据，不同结构会带来不同访问规则。顺序表练习增删查改，链表涉及指针与动态内存，栈与队列区分后进先出和先进先出，二叉树则连接遍历与递归。抽象定义由这些具体操作落到代码里。

## 阅读时可以关注什么

可以先看结构如何表示数据，再查看初始化、插入、删除与访问的入口。对于指针结构，留意节点之间怎样连接；对于栈与队列，关注边界与状态；对于树，沿着遍历顺序追踪一次递归展开。

这些是阅读学习代码的建议，并非新增的项目验证结果。公开 README 提供编译运行示例与注释说明，适合先选择一类结构理解，再对照相邻结构的差异。

## 基础也能连到后续项目

同一账号的高铁订票系统把车次、乘客、订单和站点区间余票组织成课程综合实验，可以作为后续阅读入口。这份基础仓库定位为学习参考，提醒读者理解逻辑后自行实现；记录保留下来，是为了继续练习与回看。

## 给不同结构建立同一份阅读清单

顺序表、链表、栈、队列与树都在组织数据，但它们对访问与更新的限制不同。阅读各类实现时，可以保留一份相同的问题清单：数据存放在哪里、初始化怎样表示空状态、插入会改变哪些位置、删除之后怎样保持结构有效，以及边界情况如何被表达。

| 结构 | 阅读关注点 |
| --- | --- |
| 顺序表 | 容量、元素移动与下标边界 |
| 单链表 | 节点连接、头部处理与内存释放 |
| 栈与队列 | 进入和离开的顺序、满与空的状态 |
| 二叉树 | 节点关系、递归出口与遍历顺序 |

这些是理解代码的方法，不代表仓库已经实现或验证了所有边界处理。遇到不清楚的地方，可以先画一张操作前后的结构图，再回到代码寻找对应变化。

## 用少量数据追踪一次操作

不必一开始就放入很多元素。使用几个容易辨认的值，逐步记录初始化、插入、查询和删除之后的状态，往往更容易发现自己对逻辑的误解。对于链表，可以画出节点间的连接；对于树，可以标记一次递归怎样展开与返回。

后续阅读高铁订票课程实验时，这些基础会继续出现：同一类信息如何被组织，订单引用了什么对象，一次业务更新怎样改变多处状态。基础练习与综合实验可以彼此参照，但学习仓库仍应作为理解与自行实现的入口，而不是直接替代课程中的独立练习。
