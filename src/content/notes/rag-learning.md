## 把回答前的步骤展开

这个面向小学教育的 RAG 练习，从 PDF 的结构化解析开始，经过语义增强、分块和向量索引，再进入查询改写、召回、重排、过滤与生成。公开 README 把各段思路分别列出，便于观察资料怎样一步步成为回答的依据。

解析使用 MinerU 处理布局、表格和公式；分块先依据 Markdown 结构组织章节与知识点，再通过递归切分控制长度。文件哈希检测避免重复处理未修改资料，删除文件的清理逻辑则帮助保持数据源与索引一致。

## 召回之后还需要选择

向量表示采用 bge-m3，查询改写补充上下文与指代信息。召回后的候选片段再由 Cross-Encoder 重排，并经过阈值过滤。生成部分区分新题目的解答与延续对话，历史记录保留有限轮次。

这些配置描述的是项目的实现选择，不能单凭一个阈值就证明回答不会出错。README 也留下了具体问题：复杂问题需要较多资料，简单问题可能受到无关片段干扰；英文词形变化还可能影响召回。

## 把未解决的问题留下来

知识库动态维护、文档质量过滤、标签增强和检索数量调整都仍在待改进清单中。代码由 AI 辅助并使用现成模块。作为学习记录，它的价值也在于把当前思路与下一步问题同时保存，方便继续检验。

## 按一份资料的旅程阅读代码

一份 PDF 进入知识库之后，先变成结构化文本，再经过分块与表示进入索引。用户提出问题后，系统才开始查询改写、候选召回、重排与生成。可以把这两条路径分别画出来：资料处理路径关注内容怎样被保存，查询路径关注内容怎样被选中。

阅读时，先看一个章节怎样变成片段，再看片段携带的来源与上下文，最后查看它如何进入生成阶段。标题、表格和知识点的切分方式，会影响读者能否回到原文核对回答。因此，检索结果不只是字符串集合，也是一组有出处的信息线索。

## 把“能生成”与“有依据”分开检查

可以保留一个小型阅读检查表：问题涉及的章节是什么、召回片段是否覆盖这些章节、重排之后留下了哪些依据、最终回答有没有超出这些依据。它是一条自行检验的路线，并不代表当前项目已经完成系统性的效果评估。

当答案不理想时，先判断资料是否被正确解析与入库，再判断问题是否找到了相关片段，最后查看生成过程怎样使用这些片段。这样比立刻更换模型更容易定位当前流程中的具体问题。

## 待改进清单也属于内容

公开 README 同时保留了知识库动态维护、标签增强和检索数量调整等问题。简单问题与复杂问题对候选数量的需求可能不同，历史上下文也可能改变一次查询的含义。把这些观察写清楚，后续尝试才能比较同一条路径上的变化。这里记录实现选择与学习线索，不宣称回答可靠性或教学效果已经得到验证。
